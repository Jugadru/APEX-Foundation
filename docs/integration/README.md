# APEX Foundation v0.5.0 — Ecosystem Integration

Unified offline SDK and CLI. Existing tools remain independently usable. Explicit static route table; capabilities are never executed from registered method strings. No subprocess, dynamic import, arbitrary file paths in gateway arguments, network, credentials, remote dispatch, native installation or release. Reader/planner are local intent profiles, not authentication. Direct legacy CLIs remain available for separately authorized local input. Gateway blocks arbitrary ZIP or remote jobs. Exact SHA, request/response contracts, deterministic result digest, and no execution authorization. Result is separate from closed response metadata.

```sh
python3 tools/apex.py doctor
python3 tools/apex.py catalog
python3 tools/apex.py call data.convert 180 kmh mps
python3 tools/apex.py call content.inspect vehicle.demo 1.0.0
python3 tools/apex.py request docs/integration/request.example.json
python3 tools/apex.py scenario
python3 tools/apex.py drift
python3 tools/apex.py debt
python3 tools/apex.py plan core2 524bd90a19aeaafe6920b4cdb774c77729d78fbd
```

Use call --profile planner for planning operations; structured requests accept architecture-change or mod-selection schemas instead of arbitrary input file names. Asset plan accepts fixed original/blocked example aliases. Python SDK: add tools to sys.path in a trusted local process, import apex_sdk; sdk=apex_sdk.FoundationSDK(); sdk.call("data.convert",["180","kmh","mps"]). Session reuses component instances; returned reports are detached copies. Start new session after metadata edits. This is not a sandbox for Python callers.

Doctor distinguishes local structure from native readiness. Scenario joins dataset record, content, mod preview, config, migration and evidence in memory. Gate never approves native action. Source pins remain unchanged; observed heads separate as of 2026-11-27. Core 2 and Hyper drift; Lab matches pin. All native adoption NOT_RUN/BLOCKED. Debt registry records dependencies and acceptance. Revert PR to roll back. See ONBOARDING and ROADMAP_V1.
